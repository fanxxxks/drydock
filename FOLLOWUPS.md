# Follow-ups (P2) — known gaps left for the community

Recorded during the 2026-09-22 review-fix pass. None of these block v0.1;
all are real hardening/quality items that did not fit the P0/P1 scope.

| # | Area | Finding | Suggested direction |
|---|------|---------|---------------------|
| 1 | `pkg/registry/digest/digest.go` | The digest HEAD client sets `TLSClientConfig: &tls.Config{InsecureSkipVerify: true}` (inherited verbatim from upstream watchtower): a MITM can forge the `Docker-Content-Digest` header and influence staleness decisions. A client-side `Timeout` was added in this pass; the TLS posture was deliberately left untouched because self-signed-registry users depend on it. | Add `--registry-tls-skip-verify` (default `false`, i.e. verify) or per-registry CA config, mirroring `--notification-*-tls-skip-verify`. |
| 2 | `pkg/registry/auth/auth.go` | `forbiddenRealmHost` classifies literal IPs and `localhost` names only. A public-looking DNS name that resolves to a loopback/private address (DNS rebinding) still passes the realm check. | Resolve the realm host before the request and validate every resolved IP against the same ranges (ideally pinning the resolved IPs on the dialer to defeat TOCTOU). |
| 3 | `pkg/registry/auth/auth.go` | A hostile registry can still point the bearer realm at a *different public* https host it controls (cross-host public realms are legitimate — Docker Hub uses `auth.docker.io` while the registry is `index.docker.io`). Credentials scoped to that registry would be handed to the attacker's server over TLS. | Opt-in `DRYDOCK_REALM_ALLOWLIST` for strict environments; document that registry credentials are only as trustworthy as the registry. |
| 4 | `pkg/rollback/restore.go` | `RollbackResult.FailedLogs` (tail 50 lines of the failed container) is captured but never surfaced — `gateReplacement` (internal/actions/safety.go) does not write it into the CycleReport or notifications, so operators must `docker logs` the `drydock-failed-*` container themselves. Deliberately conservative (log lines can embed secrets); still worth doing with redaction. | Add FailedLogs (truncated, optionally redacted) to `safeflow.RollbackReport` behind a flag, e.g. `--rollback-report-logs`. |
| 5 | `pkg/rollback/snapshot.go` | Env redaction covers `Config.Env`, but other inspect fields can carry secrets too (labels like `com.example.token`, bind-mount strings with `?auth=` params). | Full at-rest encryption of snapshot+sidecar (symmetric key from env/secret service) as a `--snapshot-encrypt` option; also consider redacting well-known secret-shaped label values. |
| 6 | `pkg/rollback/snapshot.go` | Orphaned `.env` sidecars can outlive their `.json` if the JSON file is deleted externally (prune removes both, but external deletion is invisible). A crash between the two writes is already handled (sidecar-first ordering + rollback removal). | Startup sweep deleting `.env` files whose `.json` counterpart is missing; log what was cleaned. |
| 7 | `cmd/root.go` | CLI usage string (`Use: "watchtower"`) and the startup message still say "Watchtower" (documented as deliberate in MIGRATION.md item 6). | Rename behind a deprecation window per the README roadmap. |
| 8 | health gate | One global `--health-timeout` for every container; slow starters (big JVM apps) force a global 60s+ budget for everyone. | Per-container label override, e.g. `com.drydock.updater.health-timeout=180s`. |
| 9 | `pkg/precheck` | v0.1 performs no network fetch of release notes; when v0.2 adds changelog pulling, reuse the hardened `limitedHTTPClient` pattern from `pkg/registry/auth` (timeout, redirect policy, `io.LimitReader`, https-only) and render as plain text — never pass fetched HTML/markdown through to notifications. | Prebuild a shared `pkg/safehttp` helper so auth/digest/changelog all use one client. |
| 10 | `pkg/rollback/restore.go` | Rollback recreates by local image ID; if the old image was pruned from the host, rollback aborts with `ErrRollbackImageMissing` even though `RepoDigests` could re-pull the exact old digest. | Fallback: construct `repo@sha256:<digest>` from the snapshot's RepoDigests and pull by digest before aborting. |
